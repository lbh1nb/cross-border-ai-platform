### 08-18 周二：数据洞察 Agent 联调（v0.6.1）

**产出物**：`scripts/insight_agent_smoke_test.py`

- 用 Mock LLM，不消耗 API 额度，可在 CI 中运行
- 5 步验证全部通过：数据生成 / 异常检测 / LLM 分析 / 卡片生成 / 表格文本

#### 任务②：异常检测增强（14:00-18:00）

**产出物**：
- `src/ai/agents/anomaly_detector.py` — 硬规则异常检测模块
- `src/feishu/card_templates.py::build_anomaly_alert_card` — 红色异常预警卡片模板

**核心改动**：
1. `fetch_daily_data` 增加前一天数据拉取，支持环比跌幅检测
2. `analyze_daily_data` 把硬规则异常检测结果作为补充上下文传给 LLM
3. `save_insight_report` 检测到异常时自动标红表格"异常标记"字段 + 推送红色预警卡片

**检测维度**：

| 维度 | 阈值 | 严重程度 |
|------|------|----------|
| 销量跌幅 | 环比 > 30% | warning（30-50%）/ critical（≥50%） |
| ACoS 过高 | > 50% | warning |
| 库存紧急 | 可售天数 ≤ 7 | critical |

**设计亮点**：硬规则 + LLM 双保险，LLM 失败时也能告警

#### 任务③：A/B 对比报告（20:00-22:00）

**产出物**：`scripts/ab_compare_insight.py`

- 评分维度：结构完整性 / 异常识别 / 建议可操作性 / 表达清晰度 / 业务价值
- 支持 Mock 模式（默认）和真实 API 模式（`--real` 参数）
- 生成 `docs/ab_compare_report.md` 对比报告

**Mock 模式对比结果**：Claude 25/25 vs GPT-4o-mini 18/25（Claude 在建议可操作性和业务价值上领先）

### 08-19 周三：双 Agent 联动（v0.7.0）

#### 任务①：双 Agent 联动① 选品 → Listing（09:00-12:00）

**产出物**：
- `src/ai/agents/listing_agent.py` — Listing 优化 Agent 主流程，ReAct 模式，recursion_limit=10
- `src/ai/agents/listing_tools.py` — 3 工具：fetch_pending_listings / optimize_listing / save_listing（含 Mock LLM 兜底）
- `src/feishu/field_mapping.py` — 新增 LISTING_FIELDS / LISTING_PRIMARY_KEYS / picks_to_listing_records 转换函数
- `src/feishu/sync_service.py::create_listing_sync_service` — Listing 库同步服务工厂函数

**核心改动**：
1. 选品 Agent 输出的 top_picks 通过 `picks_to_listing_records` 转换为 Listing 库记录
2. 按 ASIN 主键增量同步写入 Listing 库（状态="待优化"）
3. Listing Agent 自动拉取"待优化"记录，生成优化标题/五点描述/关键词/建议
4. 优化结果按 ASIN 主键更新回 Listing 库（状态="已优化"）+ 推送联动进度卡片
5. 未配置 API Key 时用 Mock 模板化规则生成优化文案，接入 Key 后自动切换真实 LLM

#### 任务②：双 Agent 联动② 洞察 → 选品复盘（14:00-18:00）

**产出物**：
- `src/ai/orchestrator.py::run_insight_to_selection_review` — 场景②入口函数
- `_REVIEW_TRIGGER_KEYWORDS = ["复盘", "选品", "爆款", "上升", "增长"]` — 5 个触发关键词

**判断逻辑**：
- 检查数据洞察 Agent 输出的 `top_priority` 和 `action_items` 是否包含复盘触发关键词
- 命中关键词 → 自动触发选品 Agent 重跑对应品类
- 未命中 → 返回"无需复盘"，状态直接转 COMPLETED

#### 任务③：Agent 编排引擎（20:00-22:00）

**产出物**：`src/ai/orchestrator.py`

**状态机设计**：
- 5 个核心状态：IDLE → SELECTING → SELECTED → LISTING_OPTIMIZING → COMPLETED（+ FAILED 兜底）
- 纯 Python 实现，不依赖 LangGraph StateGraph（流程状态明确，纯 Python 更直观可控）
- 依赖注入设计：`Orchestrator.__init__` 接受 `selection_runner` 和 `listing_runner` 可调用对象，测试时可注入 Mock
- 支持进度回调（`progress_callback`），便于 GUI 实时显示联动进度
- 失败可重试，状态转为 FAILED 并记录错误

**联动进度卡片模板**（`src/feishu/card_templates.py::build_orchestration_card`）：
- 7 种阶段颜色映射：selection_started(blue) / selection_done(green) / listing_started(blue) / listing_completed(green) / review_triggered(orange) / no_review_needed(grey) / failed(red)
- 统计字段两列布局 + 优化样本展示（前 3 条）+ 后续动作建议 + 跳转按钮

**GUI 升级**（`src/gui/pages/ai_agent_page.py`）：
- 升级为三 Tab 设计：选品分析 + 数据洞察 + 双 Agent 联动
- 场景①：下拉选品类 + "🚀 启动联动"按钮 + 实时日志显示
- 场景②：粘贴洞察输出 + "🚀 触发选品复盘"按钮 + 触发结果反馈
- `OrchestrationWorkerThread` 后台线程执行编排引擎，不阻塞 UI

#### 测试覆盖

- 覆盖：状态机转换 / 场景联动 / Mock 兜底 / LLM 失败回退 / JSON 提取 / 复盘关键词判断 / 状态写回
- AI 模块测试总计 190 个全部通过
